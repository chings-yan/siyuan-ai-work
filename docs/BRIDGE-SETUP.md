# Bridge 配套：启动、配置和配对

普通文档可直接开始，持续工作可建立 Work；文档导航和资料管理可先使用。Bridge 只为可选 AI 与 EKKO 连接提供本机访问；原生任务另由思源已启用的任务插件提供。

## 一个插件与可选配套

本发行提供一个主插件包和可选的 `bridge-companion.zip`；Hermes 服务、Studio 和旧会话适配包含在同一配套中，不需要用户判断 CLI 版本或选择插件轨道。在独立目录解压，避免混合旧脚本。配套包已将运行依赖打入入口，无需 npm 安装；使用开发源码则先执行 npm ci。需要 Node.js 24；本次发行声明 Windows 桌面支持，最低思源版本为 3.8.4。其他平台的命令作为配置参考，尚未完成实机验收。

Work 可先使用，EKKO 不必配置。已有安装更新前先核对代码、设置、旧关系和备份。历史日常源码保留作回归与回退依据，不是另一项市场安装选择；不要用旧插件数据覆盖新增关系。内部 `shared-service` 标识用于配套核验，不要求用户选择轨道。

## 准备与启动

1. Windows 在解压后的配套根目录双击 `prepare-bridge.cmd`；Linux/macOS 在配套目录运行 `node scripts/pair.mjs`。它只创建或复用 Bridge 自己的私有凭证文件，显示文件位置和下一步提示，不显示凭证、不修改思源数据。有效旧文件原样保留；空、损坏、符号链接或不安全权限的文件会失败。
2. Windows 双击配套根目录的 `start-bridge.cmd`；Linux/macOS 运行 `node scripts/bridge-supervisor.mjs`。默认回环地址为 http://127.0.0.1:8782。此命令在前台维持 Bridge；保持窗口运行，停止时在该窗口按 Ctrl+C。日志和实例锁与 Bridge 状态保存在同一用户数据目录。无需修改系统任务调度或安装服务。
3. 在插件设置选择对应回环地址。从第一步显示的本机私有文件手动复制 Bridge 凭证到密码输入框，点击“重新检测”，仅只读核验、不保存候选配置。不要发到聊天、截图、日志或共享目录。插件先核对 Bridge 健康与能力认证；输入在只读检测后保留，明确确认并保存成功后才清空。
4. 查看已配置服务的检测结果：首次仅一个可用 Hermes 服务时提出候选；多个可用时选择实际要使用的服务，再点击独立的“确认连接”。确认会重新核验，通过自身数据接口保存并读回设置。候选选择保存成功才生效。已确认的目标跨重载保留；失联时不自动切换。Bridge 配对成功与 Hermes 认证/读取能力分别显示，EKKO 独立。重连只读检查原会话，不创建、关联或发送测试问题；ready 不表示模型生成或停止已验收。

Bridge 凭证与 Hermes Serve 凭证、Studio 短期授权和 EKKO 账号密码用途不同。只有用户明确操作，插件才关联会话或发送业务内容。

Windows 两入口先检查当前可用的 `node.exe` 主版本是否为 24，再运行本包脚本；缺失或版本不符时显示 Node.js 官方安装地址与本说明，不自动安装、不改 PATH。入口不接收或转发参数，也不自动配对后启动。已有可用部署继续使用原启动方式，不必重新配对或启动第二个 Bridge；重复启动仍由原实例锁拒绝，不结束其他进程。

入口通过带引号的自身目录定位脚本，关闭延迟展开，不切换调用者的工作目录；中文、空格、`&` 和 `!` 路径的原生验收见下表。明确的相对环境配置仍以调用者 cwd 为基准。需要指定环境变量时，从已设置好变量的命令提示符调用对应入口；不把参数文本当作配置。例如在调用者目录设置 `SIYUAN_BRIDGE_ENV_FILE=selected.env` 后，使用 `call "C:\配套目录\prepare-bridge.cmd"` 或 `call "C:\配套目录\start-bridge.cmd"`。`bridge.local.json` 的相对路径仍以代码根为基准。

错误时，Windows 自带 `timeout.exe` 让有控制台输入的窗口最多停留 15 秒，可按任意键提前结束；自动调用可重定向标准输入（例如 `call "C:\配套目录\prepare-bridge.cmd" <nul`），此时不等待。停留后仍返回原脚本退出码；Node 检查失败返回 1。若需持续查看错误，先打开命令提示符再调用入口。源码中的两个 cmd 在打包时原样放入配套 ZIP 根目录，应运行解压后的入口。

### Windows 本机独立验收接力

下表列出的完整原生验收尚未全部完成。本次已在 Windows CMD 中完成两入口、三类路径与 0/37 退出码的 12 项合成子脚本检查；这不代表真实双击、ACL、配对或服务验收。其余项目仍使用独立临时副本、虚构凭据/服务和显式的临时数据目录，不针对现用 Bridge、授权、思源数据或占用端口做失败试验。运行前记录临时根和预期端口，结束只关闭自己启动的临时进程。

| 临时场景 | 本机核对 |
| --- | --- |
| 缺少 Node / 可用 Node 主版本不是 24 | 只在测试命令进程中选择隔离运行时环境；两入口显示安装说明、返回 1，不写状态、不自动安装 |
| 中文、空格、`&`、`!` 的解包目录与不同调用者目录 | 双击及命令调用均定位本包脚本；调用时正确引用路径，`!` 路径使用关闭延迟展开的调用者；检查命令行及环境中这些字符不会变成命令 |
| 首次准备 / 有效既有凭据 | 仅临时私有文件被创建；第二次准备原字节与权限保持，输出只有文件位置与固定提示、不含凭据 |
| 空、损坏、链接、错误路径或不安全 ACL | 准备失败并保留旧文件；在临时 ACL 拒绝目录中不写入凭据、不放宽权限 |
| 启动前未准备 / 已有临时实例 / 外部虚构服务占用临时端口 | 保留原配对失败、实例锁和占用错误行为；不自动 pair、不杀占用者；核对日志，Ctrl+C 仅停止本次前台运行 |
| 显式相对环境文件、进程变量与本地映射同时存在 | 从另一调用者目录调用，配置优先级及解析基准与原 Node 命令相同，子进程使用同一绝对路径 |
| 双击错误 / `<nul` 自动调用 / 合成子脚本退出 37 | 双击错误可读且最多停留 15 秒；重定向输入不等待；用临时替换的合成脚本核对退出 37 仍返回 37，成功退出无停留 |

记录 Windows/Node 版本、调用方式、每项退出码与临时文件是否保持；凭据内容不进入记录。Linux/macOS 本轮保留命令方式，未新增或声称完成其原生启动体验。

已有可用配套继续按原身份与授权使用，前端与配套版本不同不会强制拒绝。若确需更新配套，请先确认自己的原部署范围，保存内容、确认空闲并备份，再沿用原启动方式更新；保留原凭据、专用授权、正式关系与未决记录，不重新配对或启动第二个实例。设置中的“上次”状态只供参考，点击检测后查看“本次”结果。Studio 的未知归属会话不作为关联候选；已核实的会话继续按原身份与历史证据校验，不猜默认归属。

## 用户数据与配置

默认用户目录：Windows 的 LOCALAPPDATA/siyuan-ai-collab；macOS 的用户 Library/Application Support/siyuan-ai-collab；Linux 的 XDG_DATA_HOME/siyuan-ai-collab（未设置时为用户 .local/share/siyuan-ai-collab）。代码目录按当前配套脚本定位，不依赖原开发机目录。

公开 scripts/.env.example 仅给地址和空路径示例。可复制到自己的私有配置文件，并在启动进程设置 SIYUAN_BRIDGE_ENV_FILE 指向它；兼容既有 SIYUAN_HERMES_ENV。默认不扫描或读取其他产品的环境文件。优先顺序：进程已设置环境变量、显式环境文件、可选 bridge.local.json 路径映射、用户目录默认。指定的环境文件不可读时明确失败。空路径使用通用默认。先由进程或所选环境文件确定最终代码根，再读取该代码根的本地映射，避免混入另一部署的状态。本地映射用于保留路径默认，不负责切换代码根。

相对路径规则：进程变量和所选环境文件中的路径都以最初启动命令的工作目录为基准；bridge.local.json 中的相对路径以它所在的代码根为基准。环境文件路径、状态文件和子进程路径在配置加载时转为绝对路径，再交给 Bridge 子进程，因此从其他目录调用入口仍保持一致。只读取一个所选环境文件，不递归读取文件中指向的其他环境文件。

路径与凭证的来源优先级同样适用：只显式覆盖原绑定文件时，V2 默认跟随其目录；只覆盖 EKKO 连接文件时，未决标识默认跟随其目录。分别显式设置 V2 或未决目录时保留该设置。高优先级 SIYUAN_BRIDGE_TOKEN 内联凭证覆盖低优先级 TOKEN_FILE；同一来源同时设置 TOKEN 与 TOKEN_FILE 时保留旧规则，优先使用文件。推荐使用私有凭证文件；不在示例、分享内容或命令日志中写凭证值。

| 变量 | 用途 |
| --- | --- |
| SIYUAN_BRIDGE_PROJECT_ROOT | 显式代码根目录；一般无需设置 |
| SIYUAN_BRIDGE_DATA_DIR | 私有运行数据根目录 |
| SIYUAN_BRIDGE_HOST / SIYUAN_BRIDGE_PORT | 127.0.0.1 或 ::1，以及 1–65535 端口；启动与健康检查一致 |
| SIYUAN_BRIDGE_TOKEN_FILE | Bridge 能力凭证文件 |
| HERMES_STUDIO_TOKEN_FILE | Studio 自己维护的短期授权文件；默认用户 .hermes-web-ui/profiles/default/.model-run-token |
| SIYUAN_BRIDGE_BINDINGS_FILE / SIYUAN_BRIDGE_BINDINGS_V2_FILE | 既有 Studio 原绑定 / 正式 V2 绑定，保持各自迁移与身份规则 |
| SIYUAN_EKKO_CONNECTION_FILE / SIYUAN_EKKO_PENDING_DIR | EKKO 私有应用连接 / 未决发送标识 |
| SIYUAN_BRIDGE_LOG / SIYUAN_BRIDGE_LOCK | 启动日志 / 实例锁 |
| HERMES_STUDIO_URL | Studio 的本机地址 |
| SIYUAN_HERMES_SERVE_URL / SIYUAN_HERMES_SERVE_TOKEN_FILE | 显式配置的本机 Hermes 服务（Serve） 及独立授权文件 |
| SIYUAN_HERMES_SERVE_PROFILE | 显式配置的后端 profile；Desktop 有 remoteProfile 映射时，须与映射后的值一致 |

本机旧部署可使用项目根 bridge.local.json 保留既有路径。它仅含路径，必须留在本机并从源码分享、ZIP 和备份分享清单排除；新配套包不携带它。切换数据目录前自行备份并明确核对既有绑定、EKKO 未决标识，不能把空目录误当原关系丢失。不自动迁移、覆盖或轮换凭证。

## Desktop 与插件共用后端

公开接口核对记录为官方 Hermes Desktop v0.21.6+195、提交 `3b0dc776b6602b0dd05429d7842bb143d73434b7`；此记录不是连接版本门槛。检测核对安装身份、认证 ping 和会话列表结构；打开既有会话时另行核对历史读取身份、profile 与锚点，不按版本号推断可用。Desktop 默认可使用自己启动的临时端口和授权；本配套不读取、复制或自动接管它们。既有普通 Serve 占用其他端口时，上游也可能拒绝再启动指定端口。

Desktop、Studio 与 CLI 可以复用同一个核心；是否共享会话取决于服务实例、安装身份与实际后端 profile。打开另一款桌面程序不会自动改变配套已有配置。Studio 检测使用认证的会话索引与列表读取；旧 API 只验证列表并供既有会话关联，不开放新建。

本机先只读核对已运行后端和实际访问的后端 profile；Desktop 的界面标签与配置的 remoteProfile 可以不同，以后者为准。已有明确配置的共享 Serve 时，复用其已核实地址、授权文件和安装身份；需新建共享后端时，由用户选择切换现有 Desktop 连接，再按配套示例设置命令、固定回环端口、私有 Serve 授权文件，最后让 Desktop 与 Bridge 指向它。不要直接结束陌生服务、换一个空端口假装共享，或添加隔离启动参数。

需准备共享后端时，在 `scripts/hermes-serve.env.example` 显式配置已有 Hermes 的可执行文件、固定回环端口和私有授权路径。先运行 `node scripts/hermes-serve-launcher.mjs --setup` 准备 Serve 凭证，再运行 `node scripts/hermes-serve-launcher.mjs` 保持服务；授权路径与 Bridge 的 `SIYUAN_HERMES_SERVE_TOKEN_FILE` 应指向同一文件。Serve 凭证和 Bridge 配对凭证必须分别核对。

Serve 启动器只在健康和身份核对通过后保持自己启动的进程；明确配置拒绝或未就绪就退出时停止并提示，不反复重启。在 AI Work 的 Hermes 设置中检测；多个服务可用时明确选择“Hermes 服务”或“Hermes Studio 服务”。列出会话和读取历史不会提交测试问题或自动关联。已确认目标仅用于之后的新建与关联；已有 Studio Chat 继续使用 Studio 来源，旧会话服务仅供明确关联。来源不明或旧 v1 关系保留待核对，不按名称猜测、不覆盖原数据。

只读历史每页 500 行，带明确 profile 和认证头；完整读回才成功。锚点、会话身份或 profile 不符时停止，不删除旧证据。普通回环文字会话已做源级核对；启用额外身份门禁或需要 Desktop 的澄清、权限批准、sudo 等交互，须单独核验，不能把文字模拟测试称为所有能力兼容。

## 私有权限

首次创建时先核验目录，再限制新空文件权限，核验通过后才写随机凭证。Windows 实际核对 ACL；chmod 不能代替 ACL 验证。已有文件或目录不安全时拒绝，不自动更改其权限。可使用自己的私有用户目录重新准备；若要修复已有部署，先备份并人工核对权限和原凭证。本配套不会批量修改系统目录权限。

## 故障核对

- Bridge 未响应：确认启动窗口仍在、地址和端口一致，查看本机日志。端口占用时先确认占用来源；不要结束陌生服务。重复启动由实例锁拒绝。
- “凭证尚未准备”或权限错误：先运行 pair，核对显示的文件位置和私有权限。已有空或损坏文件需人工核对，禁止直接覆盖以免遗忘配对。
- 健康可达但能力认证失败：核对复制的是 Bridge 凭证，核对地址是否属于当前配套；插件不保存验证失败的候选凭证。
- 缺少服务授权凭证：配置该服务自己的私有凭据文件。Studio 使用既有短期授权，Hermes 服务使用独立 Serve 授权；不要复制 Desktop 私有登录凭据。
- Hermes 原服务拒绝授权：核对原服务的授权设置，拒绝原因未细分时不直接判为过期，Bridge 配对不能替代服务授权。
- 缺少必要读取能力：核对实际服务与配套配置，必要时更新；旧配套的 configured 状态尚未核验，不凭版本号视为兼容。未知 WebSocket 握手失败不能可靠区分认证原因，会保守提示协议核对。
- Hermes 服务未运行：先核对原进程和所有者；需要显式准备共享后端时参考启动器配置。它只管理自己启动的进程，不结束陌生占用者，也不自动改连 Studio。Serve 原有安装身份核验、停止和恢复流程保持。
- Hermes Desktop 更新页显示 GitHub HTTP 403：这是上游版本检查限流，分别核对，不用重新配对 Bridge 来处理更新检查。
- EKKO 发送结果未知：先在 EKKO 核对原消息和应用连接，再按插件提示处理本地未决记录；不因重启或更换账号清空它，也不直接重发。

## 引导、维护和安全诊断

设置按“准备本机配套 → 配对本机 Bridge → 选择 Hermes 服务 → 确认连接结果”四步展示，普通文档与 Work 均可先用，EKKO 独立可选。“重新检测”不写设置，“确认连接”才触发核验、保存和读回；配对可保存但 Hermes 不可用时不宣称目标已确认。关闭、更改候选或切页后，旧响应不能覆盖本次状态。保存结果未知时先核对，不重复提交。

维护入口仅展开静态说明，不签发、替换、撤销或自动续期授权。Hermes 有效期由原服务管理，当前未提供，不解析 JWT 推断有效期。EKKO 可展示经校验的应用登录签发到期记录，七天内提示维护；它不是实时认证证明，已过期时本次不验证服务认证，原服务拒绝或身份不符优先显示。

新版在认证后的连接响应中报告运行构建和有限能力；磁盘清单不能证明活跃进程版本。界面标为“配套报告的版本”，旧版或异常辅助字段仅降级信息，不放宽原身份、profile、历史锚点、分页或未决保护。

“查看诊断摘要 → 复制诊断摘要”只用已有结果，不新增网络请求或上传。白名单仅含插件/配套版本和有限能力、检测时间与新鲜度、完成状态、Bridge 认证状态、固定服务类别与状态、可选的部分会话归属提示代码、候选/确认类别、保存结果、实际检查错误码与 HTTP 状态；不含凭据、账号/设备/会话/房间 ID、profile、安装身份、完整地址、私有路径、文档标题/正文、原始响应或堆栈。复制失败可手动选择同一预览。
