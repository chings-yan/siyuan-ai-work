# 思源 AI Work

把文档、资料、任务与 AI 对话放在同一个工作上下文中。零散文档可以直接使用，持续推进的事项可以整理为 Work；Hermes 对话和 EKKO 房间按需连接。

- 版本：0.3.19
- 作者：chings-yan
- 平台：Windows 桌面，思源笔记 3.8.4 或更新版本
- 许可证：AGPL-3.0-only，完整条款见 [LICENSE](LICENSE)

## 安装与开始

首次上架完成后，可在思源“设置 → 集市 → 插件”搜索“思源 AI Work”。手动安装时，从本仓库 Release 下载名为 `package.zip` 的附件，解压到工作空间的 `data/plugins/siyuan-ai-collab/`；该目录根部应有 `plugin.json`、`index.js`、`README.md` 和 `LICENSE`，然后在思源中启用插件。

1. 打开一篇文档，点击 AI Work 工具栏入口进入工作台。
2. 点击“在这篇文档开始”，围绕当前文档继续阅读和讨论；首次没有当前文档时，先打开一篇。
3. 需要持续组织一件事情时，新建 Work，选择新文档或已有文档。目标、任务和 AI 都可以稍后补充。
4. 要使用 AI 时，再到“连接与设置”准备可选配套。普通文档和 Work 的整理、导航可以先使用。

## 文档、Work、任务和对话

| 对象 | 作用 |
| --- | --- |
| 文档 | 零散内容的工作入口，可独立关联多个 Hermes 对话或 EKKO 房间 |
| Work | 以一篇主文档组织持续工作，关联其他资料、任务与会话 |
| 任务 | 可选接入“任务笔记管理”插件；由原插件维护任务，AI Work 只明确关联 |
| Hermes 对话 | 在原服务、原身份下新建或接续会话 |
| EKKO 房间 | 明确进入协作房间，并逐轮选择资料与要回应的机器人 |

Work 卡片的“打开工作文档”进入主文档，“继续上次位置”才恢复最近位置；资料、任务、对话与房间计数可分别打开对应列表。Work 可在管理页设为进行中、暂停、完成或关闭；任务完成不会自动结束 Work，状态变化保留原文档和关系。

普通文档不必先建立 Work。Work 主文档下的子孙文档按实际文档树识别归属；正文链接或反链不会建立 Work 归属。已有独立文档会话不会因文档后来整理到 Work 中而自动改属。多重归属或关系损坏时先核对，不按标题猜测。

关联已有对话后，点击“打开对话”才切换。生成中的原请求、会话和修改目标按原范围冻结，浏览或切换文档不会更改该请求的目标。

### 可选任务插件

任务入口需要另行安装并启用“任务笔记管理”。原插件的许可、会员与收费规则由其作者决定。

可以查看最近未完成任务、搜索并明确关联；打开任务时使用其实际关联文档。新建任务调用原插件自己的表单或日历。打开表单不代表已经保存，保存后请回到 AI Work 刷新或搜索，并手动选择任务关联。不会按名称或最近时间猜测新任务，也不会直接覆盖原插件任务库。

## 可选 AI 配套

本插件不捆绑模型、Hermes/EKKO 应用或服务额度。使用 AI 前需自行准备兼容服务及其授权；服务费用按你实际使用的服务计算。

从同一发行版本下载 `bridge-companion.zip`，解压到独立目录；这是单独的可选配套，不能解压到插件目录覆盖插件。详细配置见配套包自带 README，以及源码中的 [Bridge 配置说明](docs/BRIDGE-SETUP.md)。

1. 安装 Node.js 24。配套已打包运行依赖，无需另装项目开发依赖。
2. 在配套目录双击 `prepare-bridge.cmd`，创建或复用自己的私有 Bridge 配对凭据。它只显示文件位置，不打印凭据，也不修改思源数据。
3. 双击 `start-bridge.cmd`，保持启动窗口运行。默认地址为 `http://127.0.0.1:8782`。
4. 在 AI Work 设置的“Hermes 连接”中输入自己的 Bridge 凭据，点击“重新检测”。检测为只读操作；选择可用服务后，点击“确认连接”才保存。
5. 已有配对可将凭据留空，保留原服务目标。多个可用服务需要你明确选择；失联时不会自动换到另一服务。

Bridge 配对凭据、Hermes 服务授权与 EKKO 应用连接用途不同。Bridge 配对成功不代表模型可用；服务读取成功也不代表生成、停止或外部工具权限已完成验收。原服务拒绝授权时，在原服务处理后重新检测，重建会话不能替代授权修复。

已有可用 Bridge 继续按原启动方式使用。前端与配套版本不同不会强制重配对或升级。若确需更新配套，先核对原部署、保存内容、确认空闲并备份，再只更新自己的配套并沿用原启动入口；保留原配置、授权、关系和未决记录，避免启动第二个实例。

## 聊天与资料选择

每次发送前选择全文、选区或仅对话；Work 资料须逐篇勾选。本轮摘要展示实际选择，Chat 固定资料只是待选清单，不会自动发送。发送前会重新读取并核对资料；超出保护上限时请缩小范围，不会静默截断。

移除固定资料不能删除旧会话里已经发出的内容。需要隔离旧背景时，请明确新建会话。Markdown 和代码可以阅读、复制；远端图片不会自动加载。

结构化修改建议需要先预览并接受。插件核对原绑定文档、原文及修改范围，逐块写入并读回；冲突或部分成功会停下并说明，普通聊天回复不会自动写入文档。

### EKKO 房间

EKKO 为独立可选连接，未配置不会阻止使用其他功能。在“设置 → EKKO 连接”配对自己的账号，关联并进入明确房间。文档、选区和 Work 资料均需本轮逐项选择并预览；房间成员和机器人可能看到发送内容。

输入 `@` 或点击“@机器人”，从当前房间已核实的候选中明确选择，选中后显示标签；标签可以移除。候选焦点和方向键只控制选择位置，点击或原有键盘确认后才选择，选择本身不会发送。按 Escape 关闭候选后可回到原输入区续写。引用中的 `@` 不会自动选中机器人。

普通完整消息可引用回复、取消引用、复制原文。引用预览和历史可展开全文；显示摘要不改变实际发送载荷。完整且来源已核实的工具记录默认折叠，可展开查看；普通正文和用户代码仍保留。

同一文档重新打开后，只有能证明原连接及房间范围保持时才自动只读核对；否则使用“刷新房间状态”。恢复不会自动发送、重发、清理未决或猜测机器人。发送结果待核对时，先按原消息标识核对，不能直接重复发送。

### 草稿与未决状态

正文、引用、机器人和资料选择属于当前运行的内存状态，按会话或房间范围隔离。关闭再打开侧栏可以保留本次运行草稿，重载插件或重启思源不会恢复未发送正文。

发送、停止或配对结果未知时，请先在原服务核对。连接恢复不代表原请求已经结束，也不会自动重发或清除待核对记录。

## 隐私与数据

插件不提供自建的云端聊天存储或支付服务。Work、正式关系、设置和未决标识保存在对应的本机存储中；发送到 AI 或房间的资料按你本轮实际选择处理。

Bridge 默认只在本机回环地址监听，使用自己的配对凭据访问。凭据、配置全文、业务文件和会话正文不应加入发行包、问题反馈或截图。设置中的诊断摘要使用固定字段；分享前仍可自行查看内容。

## 更新与回退

更新前另存未发送正文、引用和选择，等待请求、设置保存及待处理修改结束。备份插件目录和插件数据；停用插件后替换发行文件，再重新启用。只复制文件不能证明当前窗口已加载新版。

回退只还原核验过的旧插件代码，保留更新后新增文档、设置、授权、正式关系和未决记录。不要用旧数据覆盖新关系。早于 0.3.7 的版本不支持后来加入的部分独立文档/房间格式，不能直接以旧版或旧备份覆盖当前数据。

## 从源码构建

在本源码根目录使用 Node.js 24 构建和打包：

```text
npm ci
npm run build
npm run package
```

回归命令为 `npm test`，开发验证在打包前后各执行一次。当前 Windows 原始测试仍存在文件链接权限、盘符模块导入和回环端口等夹具适配限制，直接运行可能失败；本次完整通过记录来自保留全部断言的独立 Windows 适配副本，不能称为原始 Windows 全量通过。构建与打包步骤不依赖这些测试夹具。

构建包含 TypeScript 检查。发行产物为 `dist/package.zip`、`dist/bridge-companion.zip` 与 `dist/package-manifest.json`；两个 ZIP 均回读校验实际成员、CRC 和 SHA-256。运行依赖的第三方许可随配套包分发；项目 LICENSE 随两个包分发。

自动测试、受控组件验证、Windows 原生入口验证及真实服务验收分别记录在发行说明中。当前仅声明 Windows 桌面支持；Linux/macOS、纯净机器安装、真实模型生成/停止、真实房间收发和任务表单保存仍需各自验收，不能用模拟测试替代。
