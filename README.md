# Hermes 笔记助手

- 版本：0.3.26
- 作者：chings-yan
- 平台：Windows 桌面，思源笔记 3.8.4 或更新版本
- 许可证：AGPL-3.0-only，完整条款见 [LICENSE](LICENSE)

在思源里与 Hermes 对话，查找和引用笔记，同时关联文档与任务插件，打造工作空间。

- **知识检索**：侧栏“检索”页支持当前文档、当前 Work 资料，以及明确选择的全部笔记库。默认关键词；语义模式使用思源已配置的嵌入/重排服务，查询及相关候选可能交由该服务处理。插件不会代配模型、开启索引或读取密钥。搜索片段仅作线索，预览和加入引用会重新核对准确原文。房间仍只允许原来可选的文档资料。
- **采纳回答**：Hermes 完整普通回答，以及已核实房间机器人的普通完成回答，可以预览后追加到点击采纳时的当前文档末尾，或明确选择笔记本新建独立笔记。只插入新块，不覆盖旧正文；全部新增内容读回后才显示完成。暂不支持无损转换的格式可复制或明确选用纯文本代码块。同一会话的同一正文只能采纳到同一目标一次，消息编号后补不会绕过保护。结果未知时从“回复动态 → 核对文档采纳”只读核对，不重复插入。
- **任务草稿**：从回答或文档选区整理可编辑草稿，明确未完成的 Markdown 待办可分条整理。复制草稿后在原任务插件创建并保存，再准确选择已保存任务关联；打开原插件不表示任务已创建，也不会按同名任务自动关联。原任务主文档、项目和进度仍由原插件管理，Work 状态保持独立。
- **Work 模板**：新建文档时可选阅读、项目或会议模板，先查看完整预览。模板与新文档一次创建；结果待核对时不另建副本。将已有文档设为 Work 时不插入模板。
- **回复检查**：原“回复动态”增加“已关联会话”。默认手动检查，可明确开启本次启用期间的每分钟检查；只读取已关联 Hermes 会话。首次没有已读基线会明确提示，阅读后才能设置基线；历史变动或读取失败不会假报为零条新回复。不同文档关联同一远端会话时共享已读位置，各自草稿独立。检查和标读不清除任何业务未决记录。

完整历史检查需要自己的 Bridge 支持认证能力 `hermes-history-snapshot-v1`，不按版本号推断。旧配套仍保留原来的前台历史与本次回复动态；准确的跨会话检查会提示需更新配套。本候选配套新增的接口只读历史，不推进旧历史锚点、不发送消息，也不改变原正式关系、配对或服务授权。安装需在本机确认闲置、备份当前插件和配套后更新；不要启动第二个 Bridge 实例。

引用篮仍可展开准确选区与来源并查看字符量。结构化修改建议保留明确接受、写前核对和逐块读回。此前已修的完成事件正文读取、迟到事件和空白回复提示继续保留；本候选的云端合成验证不等于用户实际桌面的生成、停止或业务写入验收。

本候选允许不同文档明确关联同一个已核验的 Hermes 远端会话并共用历史。各文档保留独立的本地 Chat ID、文档根、主 Work、草稿、本轮上下文、引用、资料、固定清单和 Resume。同一文档重复关联时复用原有关系，并由“打开对话”明确切换；不会自动跳转或发送。生成、停止或关联结果待核对时保留原证据，不因重新检测、重连或重启自动清除。实际本机跨文档关联、原生安装、真实生成与停止仍待接力验收。

自 0.3.21 引入的跨文档共享需要配套支持，依据认证连接中的 `hermes-shared-session-v1` 能力判断，不按版本号推断。旧 Bridge 可继续原文档归属的兼容流程，但不提供该共享保护。更新前另存未发草稿、重新确认所有相关入口闲置、备份前端与配套代码及当前状态；保留原私有配置、配对、服务授权、关系、历史锚点和启动入口。不要启动第二个 Bridge 实例。

在思源原生文档旁持续推进工作：零散文档可直接使用 Hermes 对话，持续工作可用 Work 整理文档、任务和多个会话。Hermes 对话和 EKKO 房间均可稍后连接；不连接 AI 也能开始工作。插件 ID 保持 `siyuan-ai-collab`。

使用一个插件包和可选 AI 配套包。Hermes 服务的兼容适配由配套包处理；设置分为只读“检查本机 Hermes”和明确“使用此连接”，无需填写 Hermes 版本或选择另一种插件包。已有安装更新前先核对代码、设置与旧关系并保留备份；历史日常源码保留作回归与回退依据。

本候选保留 0.3.11 的界面优化：精简工作台卡片与任务列表，统一 Hermes/EKKO 的正文、工具按钮和输入区，并适配明暗主题及窄、矮窗口。四类计数仍可点击，房间保留输入 `@` 和“@机器人”选择，以及输入框顶部拖动条；连接、会话归属、草稿和待核对保护沿用原规则。

保留房间本人消息气泡、紧凑引用和已确认发送的临时回执，支持“引用回复”、正文拖选及原文复制。保留工具结果默认折叠：优先识别已核实房间Agent的明确工具角色和完整消息来源，并兼容独立工具搜索结果及限定格式文档大纲，展开可查看完整原文。引用可取消、保留正文草稿；要机器人回应仍需明确 `@` 选择。0.3.15 配套已提供非法标记与真正省略的区分；本轮共享功能需更新插件与配套 Bridge；原房间功能及授权继续保留。保留私有配置、配对、专用授权、关系和原启动入口，先保存草稿、确认请求空闲后再重载插件；不重新配对或换服务。

本轮修正同一文档重新打开后房间交互失效的已复现路径：能够证明原稳定连接未变且文档、Work 与精确房间仍一致时，只读重新核对房间状态；不能证明或读取失败时，输入区提供“刷新房间状态”，由你明确执行只读恢复。恢复不自动发送或重发，不清除未决，不猜测机器人。它不是对本机所有无响应原因的诊断，实际原生交互仍需安装后核验。

## 先开始使用

从本仓库 [Releases](https://github.com/chings-yan/siyuan-ai-work/releases/latest) 下载 `package.zip`，按下面步骤安装；集市安装入口以审核收录结果为准。需要可选 AI 时另取同一发行的 `bridge-companion.zip`。

1. 将插件包 `package.zip` 解压到思源工作区的 `data/plugins/siyuan-ai-collab/`，确认该目录直接包含 `plugin.json`、`index.js`、`README.md` 和 `LICENSE`。在思源插件设置中启用。
2. 点击工具栏“Hermes 笔记助手”或聊天侧栏的主页按钮，打开工作台。启动插件不会抢占当前文档。
3. 处理零散文档时，先打开该文档，再从主页点击“在这篇文档开始”打开已捕获文档和聊天侧栏；没有当前文档时先打开一篇。入口只浏览并保留原 Work/Chat，不创建关系或发送内容；之后明确用“＋”新建或关联时，才按文档实际归属核对范围。无需先建立 Work。
4. 需要整理持续工作时，点击“新建 Work”，选择新建工作文档或使用已有文档；目标和任务均可跳过。**整理 Work 不需要先连接 AI**。Work 卡片的“打开工作文档”打开主文档，“继续上次位置”才恢复最近文档或块。

首次安装没有 Work 时，主页提供文档与 AI 的可选引导；已有数据时展示真实 Work 卡片和最近任务。全部 Work 在二级列表中搜索、筛选；卡片的资料、任务、AI 对话和协作房间计数可直接打开对应分类。侧栏的 Work 名称就地展开选择菜单。

## Work、文档、任务、会话怎样关联

| 对象 | 用途 | 主要入口 |
| --- | --- | --- |
| Work | 用一篇思源文档承载一项持续推进的工作，目标可选 | 主页新建、Work 列表进入 |
| 文档与资料 | 主文档用于记录成果，其他文档可关联为资料并保持原位 | 管理 → 文档与资料 |
| 任务（可选） | 由“任务笔记管理”维护的待办，可关联到一个主 Work | 主页/侧栏任务、管理 → 关联任务 |
| Hermes 对话 | 一篇独立文档或同一 Work 可有多个对话；关联后保持当前对话，点击打开才切换 | 当前会话选择器、＋、会话管理 |
| EKKO 房间 | 同一房间可手动关联多个 Work；资料须每轮明确选择 | ＋ → 关联 EKKO 房间 |

Work 状态由你在管理页选择并确认，可设为进行中、暂停、完成或关闭，也可再次更改。任务完成不会自动结束 Work；更改状态保留文档、资料、任务和会话关系。管理页提供“完成 Work”和“恢复工作”；完成或关闭前重新读取关联任务，提示未完成任务及未知、缺失项，读取失败时明确提示核对。确认只更改 Work 状态，不修改任务完成标记、任务进度或项目状态。

### 零散文档与 Work 子文档的对话

- 普通文档可直接新建或关联 Hermes 对话，不会为此添加 Work 标记或创建额外文档。该文档的多个会话可在侧栏选择器切换；关联已有会话后，点击“打开对话”才切换。
- 确认已经关联的、可核验为就绪的 Hermes 对话后，选择框收起并显示已有关系与“打开对话”入口；新关联成功也显示结果。读取或关联失败时在选择框内提示，保留当前 Chat 和草稿供核对。关联确认不会自动打开、发送或重试；点击“打开对话”才切换，期间若已选择其他 Chat，迟到结果不能覆盖新选择。
- 独立文档的本地正式关系保存在该文档范围内；不同文档可明确共享精确远端会话及历史，本地草稿、上下文和待核对状态分别保留。重新打开文档时读取其原关联，重连沿用原会话身份。
- Work 根文档下的子孙文档按文档树识别所属 Work，无需逐篇设为 Work。只发送本轮明确选择的全文、选区或资料，不自动发送整个 Work 的全部文档。
- 正式归属多个 Work 时明确选择；普通正文引用或反链不建立 Work 归属。无法核对归属时显示错误并保留原状态。浏览无关文档后创建会话不会把它默默挂到原 Work。
- 生成或待处理修改期间，原请求、对话和写入目标保持冻结。独立会话不会因文档后来被整理到某个 Work 而自动改属。

### 创建与保存位置

- 新建工作文档默认使用“设置 → 工作文档”中指定的笔记本根目录；创建时仍可改选。选择跟随当前文档时，使用打开主页前确认的原生文档所在笔记本。没有可用默认值时必须手选。
- 使用现有文档时，表单展示并冻结所选文档；不会移动或重建原块。填写目标才在正文最上方加入目标块，留空则仅建立 Work 标记。已存在的有效 Work 直接复用；目标可在管理页稍后补写。
- “当前文档”是进入主页或打开操作表单前，插件最后确认的原生编辑器文档。主页自身不是文档；后台切页不会偷偷替换已展示的关联目标。
- 文档创建、目标写入或关联结果不明时保留核对记录，只继续已确认的后续步骤。不要重复创建。重复目标标记或正式关系损坏需先核对；没有目标本身不会阻止使用。

### 任务：最近、搜索、新建、关联

安装并启用“任务笔记管理”后，主页和侧栏显示最近未完成任务，也能按标题/备注搜索。侧栏任务菜单优先显示搜索与最近任务，其他操作可展开，支持关闭并随窗口高度调整。空搜索是最近推荐；“打开关联文档”只打开该任务实际关联的文档。无文档、文档不存在和服务失联分别提示，不改成打开 Work 主文档。

在 Work 管理中可搜索并明确选择已有任务。关联前重新读取任务与归属；已有其他主 Work 的任务不能被重新挂靠。任务关联不会切换当前文档或对话。

右侧“文档关联 → 任务”可让普通文档直接关联已有任务，无须先建立 Work。选择任务并确认后，当前文档成为 AI Work 保存的补充资料关联；原任务主文档、项目、进度及原主 Work 保留。这是 AI Work 的文档关联，不会向原任务插件添加附件或复制任务。一个任务可关联多篇补充文档，一篇文档也可关联多条任务。“移除关联”仅删除当前这对补充关系。

同名任务可通过原主文档名称、项目 ID 和可展开的任务标识区分，确认时再次展示所选身份；主文档名称读不到时明确标注。写入前重新核对原任务，收到任务更新后要求重新核对选择；不沿用过时的主文档、项目或完成状态。后台刷新保留仍存在的操作按钮焦点，目标消失时回到结果区域；不抢回已移到其他编辑器的焦点。

关联页保留已完成任务并读回原进度；打开页面、切换文档、任务更新通知、窗口重新获得焦点和“刷新”都会重新读取。读取失败或任务已删除时保留补充关系供核对，不当作已完成。可以在此点击“编辑任务”打开原任务编辑器；保存仍由原插件处理。

“文档关联 → Work”将当前文档作为外部资料关联到所选 Work，不移动文档。已经是根文档、子文档或已关联资料时显示相应状态，不重复创建链接。“打开 Work”是另一个明确操作。

关联任务列表提供“在任务插件中编辑”，仅在当前窗口的任务插件公开提供原生编辑能力时打开精确任务；能力缺失、任务不存在或结果未知会提示核对，不自动重复发起。任务名称、完成标记、进度和项目由原插件编辑并保存，入口回执不表示已保存。返回可见的 Work 页面后，任务更新通知、窗口重新获得焦点或页面恢复可见仅触发只读刷新，更新任务详情及完成计数，不根据通知内容猜测保存结果。

任务完成计数只依据任务插件的完成标记；可选进度百分比单独显示，100% 不等于已完成。无法读取的任务列为未知，已不存在的任务列为缺失，不会计为完成，也不会删除原关联。任务完成不会改变 Work 状态，Work 完成或关闭也不会完成任务。

“新建任务”调用任务插件自己的原生入口：有目标文档时打开该文档的任务表单，无文档时打开任务日历入口。名称、项目和保存由原插件处理。**打开表单不等于任务已保存**；保存后回到 AI Work，刷新/搜索并手选任务关联。插件不能可靠获知原生表单的保存结果，因此不会按名称或最近时间自动猜测关联，也不会自动重复打开创建。

任务插件未启用时可先使用 Work；启用后重试。当前适配依据任务插件 7.1.2 的公开命令、可用时的公开原生编辑能力和只读 MCP；不会直接读写任务数据文件，也不调用任务 MCP 写接口。原生能力按实际接口检测，不凭版本号假定可用。

## 可选 AI 连接

首次使用 AI 可准备本候选提供的 `bridge-companion.zip`。插件包本身不包含 Node.js、Hermes 或 EKKO 服务。将配套包解压到独立目录，按其中 README 准备；已打包运行依赖，无需安装项目开发依赖。

已有可用的旧配套继续按原认证与原文档归属规则使用；版本不同不会强制拒绝连接。缺少能力信息会显示“配套未提供可识别的能力信息”。本轮跨文档共享需要更新配套并核验认证能力；只更新前端不会改变旧 Bridge。更新和重启前须新鲜确认闲置、备份当前代码与保护状态，保留原私有配置、配对、服务授权和会话关系，按原入口重启同一实例。

1. 安装 Node.js 24（本地组件核验使用 24.15.0，云端源码核验使用 24.19.0）。Windows 在解压后的配套根目录双击 `prepare-bridge.cmd`；Linux/macOS 在配套目录运行 `node scripts/pair.mjs`。此步准备或复用本机私有 Bridge 凭证，只显示文件位置，不打印凭证，不改思源数据。
2. Windows 双击配套根目录的 `start-bridge.cmd`；Linux/macOS 运行 `node scripts/bridge-supervisor.mjs`。保持窗口运行，在该窗口按 Ctrl+C 停止。默认 Bridge 地址为 `http://127.0.0.1:8782`；127.0.0.1 表示当前电脑。已有正常运行的部署继续使用原启动方式，无需重新配对或启动第二个实例。Windows 入口、错误停留及独立临时目录验收说明见配套 README；本轮云端未执行原生 Windows cmd。
3. 在 AI Work 设置的“Hermes 连接”中，缺少配对时展开准备区域，从自己的私有文件复制 Bridge 凭证到密码框，点击“检查本机 Hermes”。此操作只读、不保存；已有凭证可留空，界面不会回显它。不要将凭证发到聊天或截图中。
4. 插件先核对本机 Bridge 身份和配对凭证，再检查已配置 Hermes 服务的认证与会话读取能力。首次只有一个可用服务时提出候选；有多个时从检测结果中明确选择，再点击卡片中的“使用此连接”。确认会重新核验、保存并读回设置，成功后才切换目标。下拉选择先作候选，保存成功才生效。已确认的选择会跨重载保留；原服务不可用时不自动改连其他服务。Bridge 配对成功、Hermes 可用、EKKO 已连接分别显示。

设置页打开时显示上次读取的各服务状态，并注明它不是实时状态；点击“检查本机 Hermes”后才显示本次结果。缺少服务授权、认证失败与读取协议不兼容分别提示，失败重试不会把旧结果标成本次检测。

Studio 列表中有部分会话缺少可核实的归属时，会提示“部分会话归属尚未核验，无法关联；已核验归属的会话可继续使用”。这些条目不会出现在可关联列表，也不会猜测为默认归属；其他已核实会话仍可使用。提示来自本次读取，后续分页发现问题也会提示；重新读取取得精确归属证据后才可选择，仍需手动确认关联。明确归属冲突、认证失败和损坏的读取协议继续拒绝。已有 Chat 的原身份、历史核验和未决状态不变。

只检测当前配置与本机默认地址，不扫描其他端口。地址只接受回环 HTTP 地址；自定义 Bridge 端口在“高级配置”中设置。检测不会发送测试问题、创建或关联对话；“读取已核验”不代表真实生成或停止已验收。更换目标只影响之后的新建与关联，已有 Chat 保留原连接、profile、安装身份和远端会话；旧会话服务只供明确关联，不支持新建。

### 重连与发送失败

已有 Chat 可以继续，不必每次新建。侧栏“重连”只读核对连接，恢复后读取原会话；授权失效需在对应服务处理。设置中的检测用于配置与诊断，不是每次发送的前置步骤。

- **尚未配置 AI**：可继续使用 Work 和任务，按需配对。
- **Bridge 未响应**：检查配套启动窗口及本机地址。
- **Bridge 凭证未通过**：核对是否连接了自己的 Bridge，并重新核对凭证。
- **服务未运行或不可达**：启动已配置的 Hermes 服务，核对地址。
- **缺少服务凭证 / 原服务拒绝授权**：分别准备或核对该服务的授权，拒绝原因不直接判为过期；Bridge 配对凭证不能替代 Hermes 授权。
- **读取协议不兼容 / 安装身份不符**：核对服务配置与原连接；必要时更新服务或配套包，不按版本号猜测连接已恢复。旧配套的“已配置”也不表示能力已核验。
- **未发送**：草稿保留，可修正后重试。
- **发送/停止结果待核对**：先在原 Hermes 会话核对历史与执行状态，再按界面提示处理；连接恢复不会自动清除未决状态或重发。

Hermes 服务读取历史使用带认证、带明确 profile 的只读接口，不调用恢复会话来获取历史。旧历史锚点仍需匹配；返回其他会话身份、不同 profile、缺页或无法证明兼容的历史投影时明确停止，不清空锚点猜测续接。握手与 RPC 保留 10 秒超时，已接受的回复单独最多等待 30 分钟；断线或超时仍显示待核对，不自动重发。

Hermes 设置常态显示一张当前连接卡片，包含当前服务、最近检测及状态；准备配对、选择候选与“使用此连接”按需出现。“更换连接”只展开候选，不保存；维护区域的“在卡片中确认连接设置”只把待确认设置带回卡片，唯一保存按钮仍是“使用此连接”。仅配对 Bridge 时保留原服务偏好。可随时选择“稍后连接，继续整理文档/Work”。连接维护、诊断和说明默认折叠；维护说明不创建、替换、撤销或续期授权。Hermes 有效期由原服务管理，当前未提供；EKKO 可显示经校验的应用登录签发到期记录，七天内提示维护，但它不保证实时认证有效。授权不会自动续期。

“查看诊断摘要”先预览，再由“复制诊断摘要”复制同一内容，不上传、不额外请求服务。摘要只包含版本/有限能力、检测时间与新鲜度、固定状态与类别、可选的部分会话归属提示代码、候选/确认类别、保存结果、实际取得的步骤错误码及 HTTP 状态；不含凭据、账号/设备/会话/房间 ID、profile、安装身份、地址、私有路径、文档标题或正文、原始响应或堆栈。配套报告版本是认证连接中的自报信息，不是代码签名证明；开发或旧配套可显示未知。

### Desktop 与插件使用同一 Hermes

Hermes Desktop、Studio 和 CLI 可以使用同一核心，但打开另一个程序并不保证连接同一个服务实例。若需要共用会话，应让 Desktop 与配套包明确指向同一后端、授权与后端 profile；有 `remoteProfile` 映射时以映射后的值为准。同一名称的会话不能作为归属依据。

本配套同时保留 Hermes 服务、Hermes Studio 服务和旧会话适配。已有 Studio 对话仍使用原来源；来源不明的旧关系保留待核对，不按名称自动绑定。检测不读取或接管 Desktop 的临时端口和私有登录凭据，也不结束已有服务。共享后端的显式配置见配套 README；普通文字会话以外的 Desktop 权限批准、澄清、sudo 等交互需在原入口处理并单独验收。

已核对的 Desktop 公开接口版本仅作为验证记录，连接判断依据实际协议响应。Desktop 更新页的 GitHub 403 是版本检查限流，应单独处理。

## 聊天与本轮资料

聊天侧栏顶部提供“对话 / 文档关联”切换，保留 Work 工具行和对话页的会话选择行。切换视图保留原聊天节点、当前会话、草稿、引用和运行，不发送消息或中断生成。AI 对话与协作房间在会话选择器中分组；同一 Work 可查看多条对话，明确打开才切换。消息独立滚动、输入区在底部。Work 快选按侧栏实际高度滚动，搜索与说明有明确间距，长标题换行；文档关联页可独立滚动到所有操作。Hermes 与 EKKO 输入区均可从顶部拖动调整高度，房间草稿与高度按房间身份隔离。消息支持 Markdown、代码与回复复制；阅读旧消息时新内容不抢滚动，可点击“回到最新”。远端图片不自动加载。

发送前选择当前文档全文、选区或仅对话；Work 资料须逐篇勾选。摘要显示本次实际选择，Chat 固定资料只是**待选清单**，不会自动发送。发送前重读并核对资料；超过传输保护上限时要求缩小范围，模型实际上下文预算未知。移除固定资料不能删除旧 Chat 中已发送的历史；需要隔离旧背景时明确新建 Chat。

Hermes 草稿按 Work 或独立文档、连接和 Chat 隔离；共享远端会话不会合并草稿、上下文、pins 或 Resume；EKKO 按 Work 或独立文档、连接、账号、设备、房间隔离；普通文档 A/B 即使关联同一远端房间，也分别保留本次运行的草稿、资料、Agent 选择与输入高度，远端历史仍共享。关闭重开侧栏保留本次运行的草稿，重载插件或重启不会恢复草稿正文。保存草稿后再更新/重载。

结构化修改建议须经过预览和接受；插件核对会话原绑定文档根、原文、逐块写入并读回。冲突或部分成功会停下并说明；普通回复不会自动改文档。切页不会改变已冻结请求的目标。仅在等待已冻结的 Hermes 请求回复时，工作入口允许打开另一工作文档或继续上次文档；原 Work、Chat 与接续位置继续保留。请求准备、设置保存和待处理修改期间仍阻止这些导航。

## EKKO 房间（可选）

普通文档可直接从侧栏 ＋ →“关联 EKKO 房间”选择有权访问的已有房间，无须创建 Work 或文档；Work 子孙文档与明确外部关联按同一权威归属规则处理，多归属须先明确选择。关联保存保留当前会话，点击“打开”或侧栏“协作房间 · EKKO”选择器才切换。归属读取失败或没有合法当前文档时停止操作并给出提示；已有独立文档房间不会因为后来出现 Work 而自动改属。

在“设置 → EKKO 连接”配对自己的账号。账号名可在 Ekko Studio 的“设置 → 当前账户”查看。默认 EKKO Studio 本机服务是 `http://127.0.0.1:8748`，以其实际启动信息为准；它不是 Bridge 的 8782 端口。

密码仅用于本次配对，提交后清空。Bridge 保存可撤销的应用连接，界面读回并显示核对后的账号；已连接时默认显示账号摘要，明确选择“更换连接”才重新输入。配对不等于关联或进入房间。关联房间与选择会话在会话入口操作，设置中不建立 Work/Chat 关系。

进入房间可查看历史、接收新消息和发送文字；离开即停止订阅。默认仅发送消息。点击输入框旁常显的 **引用文章**，展开本轮资料区，再勾选当前文档全文或合法选区、预览后发送；普通文档只提供这两类来源，Work 还提供其可选资料，均须本轮逐项勾选。打开或刷新资料区不会自动选择、附带或发送文章。重新选取原生文档选区后，点击 **重新读取可选资料**；刷新后资料区保持展开，新选区仍需明确勾选。空选区不作为可选资料；发送前仍会重读并核对所选内容，房间成员和 Agent 都可能看到。

在输入框开头或空白后输入 `@`，或点击发送按钮旁的 **@机器人**，按名称筛选当前房间已核实的机器人；鼠标/触屏点选，或用上下键后 Enter/Tab 选择，Escape 取消。选择会消耗当前 `@查询`，把机器人加入输入区旁的本轮已选标签；标签可移除，与展开区的 Agent 勾选保持同步。点击按钮选择不会改变原文字和光标，未选中的裸 `@文字` 不会唤醒机器人。发送时由现有规则生成一次 `@名称` 和结构化提及。暂不提供文件、语音、房间管理或房间消息自动写入思源。

房间阅读界面优先将当前已核实Agent、明确 `role=tool`、非用户/auth的完整历史或 `room.message` 输出折叠为“工具结果”，无须逐种猜测结果内容。`isStreaming` 是可选字段：在这些完整消息来源中，明确false可直接展示，真正省略字段还须收到Bridge本地产生的 preservesStreamingFlagPresence:true 保障；不给远端消息补false。旧配套没有该标记时只走保守结构兼容，不能按软件版本推断同样严格的保障。新配套保留被过滤非法值的字段存在性并以null表示未知，不带出非法对象；明确true只显示等待，字段存在但类型非法时不会被能力标记覆盖。原始 `room.stream` 事件无论有无该标记都仅维护活动提示，不拼入正式历史；这不代表验证工具执行已结束。陌生来源不因tool角色得到信任。兼容路径仍对明确机器人来源、严格匹配的工具定义、运行统计、工具搜索结果及限定文档大纲 JSON 默认折叠；搜索结果须具有合法计数、查询结果与一致工具清单，大纲须具有完整标题行、合法思源 ID 和一致行数。两条路径均可展开精确原文，不提供普通复制或引用回复入口，展开后可选择原文。普通assistant的JSON、说明和代码示例，用户内容与来源不明内容保持显示，不按姓名或单独 `result` / `tools` 字段隐藏。结构兼容路径只是可逆的形状判断，机器人刻意输出完全同形的普通JSON仍可能折叠，完整原文始终保留。完成的空白记录不建气泡；正式答复以完整房间消息为准。原始历史、分页和发送核对保持不变。

已完成的普通房间消息可点击“引用回复”，撰写预览与历史中的完整引用默认显示作者和两行摘要，可展开查看完整原文；可取消引用而保留正文。摘要仅影响显示，复制消息和发送载荷仍保留完整原文。引用仅保存在本次运行内，按完整房间身份隔离，离开再打开可恢复；技术记录、空白或未完成消息不可引用。引用中的 `@` 不激活机器人，仍需显式选择；引用本身不能单独发送。发送前原消息变化或删除会停止发送并保留草稿，合计超过 120000 字符明确拒绝且不截断。准备发送和结果未知时引用锁定，确认成功后清除。

同篇文档重新打开时，稳定原连接可核实且范围未变才自动只读重核对；无法确认仍是原连接，或连接已更换、读取失败时，点击输入区“刷新房间状态”，或按提示重开原房间。核对期间保留本次运行的正文、引用、已选机器人和本轮资料选择；迟到结果不能覆盖新场景。准备、提交和确认更新期间显示可见状态；活动发送不会因恢复重建输入区。若结果待核对，先使用原条消息 ID 的核对入口，不能再次发送。恢复不会自动 @、发送文章、迁移关系或解除发送前身份与资料校验。

正文、引用和机器人选择属于本次运行的内存草稿；只读恢复保留草稿不代表重载后自动恢复。更新前请另存未发送内容并确认闲置，数据文件备份不能替代另存草稿。

当前账号仅按已核验账号的精确发送者身份显示“你”和靠右的浅色气泡；消息时间显示小时与分钟，完整时间可查看提示。直接发送返回已确认后，若历史尚未返回，房间显示“已发送，等待历史同步”的临时回执；本次发送确认后会将新消息正文带入视口；阅读旧消息时，其他成员的新消息仍保留当前位置。回执可复制原文，但不能引用回复，也不参与正式历史或分页。只有准确消息 ID、房间、本人身份和完整内容均与历史一致才移除回执；未知、拒绝或发送前失败不会产生成功回执。回执按 Work 或独立文档、连接、设备、账号和房间隔离，仅保留在当前面板实例的内存，离开再进入同一范围仍可见，销毁面板或重载后不恢复。

配对或发送结果未知时先核对原应用连接/消息，不自动重试。EKKO 未决发送标识可跨重启保存，但不包含正文；更换账号、断线或撤销连接不会清空房间关系。撤销访问在 EKKO 的“应用连接”操作。

## 更新与回退

从历史日常安装接入统一候选前，先在本机核对旧关系来源和配套路径；尚未核实的旧关系保留待确认。更新前保存未发送草稿、等待请求结束，备份插件安装目录及插件数据。停止/禁用插件后替换代码文件，重新启用或重启思源。只复制文件不表示当前窗口已重载。

回退只恢复本次更新前核验过的插件代码，保留更新后新增文档、正式关系、设置、令牌和未决操作记录；**不要用旧数据覆盖新关系**。备份可能含私有凭证，不能加入分发包或分享。正式关系损坏时停止覆盖，最近位置损坏仅降级导航。

0.3.6 支持正式保存未归属 Work 的独立文档会话。创建这类新关系后，0.3.5 及更旧插件会拒绝读取新记录；回退前须核对兼容处理，并同时保留升级前备份和新增关系，不能直接恢复旧数据。

0.3.7 支持明确 null Work 与精确文档范围的独立 EKKO 房间关系和未决标识；原 Work 记录字段形状保持。新增此类记录后，0.3.6 及更旧插件会拒绝读取新房间/未决记录。回退须保留升级前备份和新增记录，先核对兼容处理，不以旧数据覆盖新关系。
